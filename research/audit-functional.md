## 3. Форма заявки (протестирована по-настоящему)

Поля: `name`, `phone`, `format` (select), `date`, `place` (select), канал связи (несколько кнопок), `comment`, чекбокс `consent`, скрытое `company`.

1. **Пустая форма.** Пока согласие не отмечено — кнопка `disabled`. После отметки согласия и отправки пустой формы показаны: **«Укажите имя»**, **«Укажите телефон»**, **«Проверьте выделенные поля.»**; у `#lead-name` и `#lead-phone` → `aria-invalid="true"` и `aria-describedby="err-name"/"err-phone"`, граница окрашивается в красный `rgb(217,139,122)`; **фокус переводится в первое проблемное поле** (`document.activeElement.id = lead-name`). Сообщения об ошибке — обычные `<p>` без `role="alert"`/`aria-live` (мелкий недочёт).
2. **Кнопка «Отправить заявку» при неотмеченном согласии — `disabled=true`.** После отметки согласия становится активной.
3. **Телефон:**
   - `abc-def` → маска вырезает буквы, поле становится **пустым** → ошибка «Укажите телефон»;
   - `+1 555 000 0000` → маска насильно ставит `+7` → в поле **`+7 155 500 00 00`** → ошибка «Проверьте номер: нужен формат +7 7XX XXX XX XX»;
   - `123` → `+7 123` → ошибка «Проверьте номер: нужен формат +7 7XX XXX XX XX».
4. **Имя из 1 символа** (`A`) → **принимается без ошибки** (`aria-invalid=false`), проверки минимальной длины нет.
5. **XSS/эмодзи/кириллица/казахский:** комментарий `<script>alert(1)</script> 😀 әл-Фараби Привет` — ничего не ломается. React **экранирует вывод**: имя `Иван <b>Test</b>` в экране успеха показано **как текст**, не как разметка. Значение уходит в текст WhatsApp корректно URL-энкоденным. Кириллица/казахские буквы/эмодзи обрабатываются корректно.
6. **Ввод `87006592307`** → в поле оказалось **`+7 700 659 23 07`** (маска `+7 …` применилась).
7. **Дата.** У поля `min="2026-10-12"` (нативный). Ввод прошлой даты `2020-01-01` даёт `validity.rangeUnderflow=true` и сообщение «Минимальное значение должно быть 12.10.2026.», **но форма имеет атрибут `novalidate`**, и её JS-валидация дату **игнорирует** → заявка с прошедшей датой **уходит успешно**. Т.е. прошедшую дату отправить можно.
8. **Honeypot** `input[name="company"]`: визуально скрыт за пределами экрана — `getBoundingClientRect` → `x = -9999`, `y = 17869` (и влево, и далеко вниз), `tabindex="-1"`. (Не помечен `aria-hidden`, но вне вьюпорта.)

## 8. Клавиатурная доступность

- **92 таббируемых элемента**, порядок логичный: скип-ссылка → шапка (лого + навигация + «Записаться») → CTA героя → кнопки серий → чипы фильтров → кадры галереи → «Спросить» по форматам → FAQ → контакты → поля формы → чекбокс согласия → «Отправить заявку».
- **Видимая рамка фокуса есть**: глобальное правило `:focus-visible { outline: 2px solid var(--brass); outline-offset: 3px }`. Для полей формы правило `.field:focus { outline: none; border-color: var(--brass) }` — рамка убрана, но граница меняется на золотую (видно). Скриншот: `shots/05-focus-ring.png`.
- До формы можно дойти и отправить её с клавиатуры (семантика `<form>`/`type="submit"`, `label[for]` связаны).
- **Лайтбокс удерживает фокус внутри** (проверено Tab, см. §4).

## 9. Консоль и сеть

- **Консоль: полностью чисто** — 0 ошибок и 0 предупреждений за визит. Нет предупреждений `next/image`, нет hydration-mismatch, нет React-warnings (проверено и mode-чтением логов, и `errors`).
- **Ответы ≥ 400:**
  - `GET /favicon.ico` → **404** (причём при первой загрузке запрошен **дважды** — дубль);
  - `GET /api/lead` → **405** (это результат моего теста; сам сайт его не дёргает);
  - `GET /work/*` и `/nonexistent-page-12345` → **404**.
- **Дубликаты запросов:** свежая загрузка — 22 ресурса, дублей нет. Единственный дубль в первом визите — `/favicon.ico` (авто-запрос браузера + повтор).
- **Offline.** Прямая эмуляция offline недоступна в предоставленном наборе инструментов. Факт по существу: **service worker не зарегистрирован** (`navigator.serviceWorker.getRegistrations()` → 0, контроллера нет) → при отключённой сети перезагрузка покажет стандартную страницу ошибки браузера (своего offline-фолбэка у сайта нет).
- **Несуществующий URL** → Next.js-страница **404** (см. §1): `404: This page could not be found.`, без утечки стека.

## Сводка проблем (приоритеты)

**High / функциональные**
1. `POST` на бэкенд **отсутствует** — заявка никуда не сохраняется, только открывается WhatsApp; при блокировке всплывающих окон или отказе пользователя от перехода **заявка теряется полностью**.
2. **Двойная отправка** → 2 вызова `window.open`, без блокировки кнопки/состояния «Отправляем…» → риск дублей.
3. `/work/love-story` и `/work/family-and-kids` → **404** (несуществующие «страницы работ»).
4. Форма `novalidate` + JS **не проверяет дату** → **прошедшую дату можно отправить**.
5. Страница 404 — дефолтная Next.js, **на английском**, без шапки/брендинга и **без навигации на главную** (единственная ссылка ведёт на битый `#works`).

**Medium**
6. **Favicon отсутствует** (`/favicon.ico` 404, `link[rel=icon]` нет).
7. У `/privacy` **нет og:image**.
8. Имя из 1 символа принимается (нет min-length).
9. `robots=index,follow` на `/privacy`.

**Low / a11y UX**
10. Лайтбокс при закрытии по Escape **не возвращает фокус** на элемент-инициатор (фокус падает на `BODY`).
11. Сообщения об ошибках формы — без `role="alert"`/`aria-live` (скринридер может не озвучить).
12. На кадрах галереи/ошибках вывода XSS нет (вывод экранируется — это хорошо), но сообщение об ошибке валидации телефона при зарубежном номере маскирует его в `+7`, что может вводить в заблуждение.
13. Свайп в лайтбоксе работает только по изображению, не по пустой области оверлея.
